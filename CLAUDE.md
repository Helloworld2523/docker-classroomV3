# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**Cyber Classroom** — ระบบ live streaming portal สำหรับนักศึกษา ม.เทคโนโลยีราชมงคล (RU) ดูถ่ายทอดสดห้องเรียน, chat ระหว่างเรียน, และ admin monitoring dashboard

## Commands

**Run (Docker):**
```bash
docker-compose up           # start django_v2 + nginx89 services
docker-compose up --build   # rebuild and start
docker-compose down         # stop
```

**Development (local):**
```bash
cd cyberclassroom
python manage.py runserver
python manage.py migrate
python manage.py collectstatic --noinput
```

**Access:** `http://localhost:8849` (through Nginx) or `:8080` (Django direct)

The `classroom_net` Docker network must be created externally before running:
```bash
docker network create classroom_net
```

**Environment:** Copy `.env.example` → `.env` and fill in `SECRET_KEY`, `DB_*` values.

## Architecture

### Services
- **Django app** (`cyberclassroom/`) — uWSGI, 4 processes × 2 threads, port 8080
- **Nginx** (`nginx89/`) — reverse proxy on port 8849, serves `/staticfiles/`, handles SSE without buffering

### Django App Structure
- **Project:** `cyberclassroom/` (settings, urls, wsgi)
- **Main app:** `live/` — all models, views, admin, templates, middleware
- **Templates:** `live/templates/live/` (student-facing), `live/templates/admin/` (custom admin UI)
- **Middleware:** `live/middlewares/learning_time_middleware.py` — blocks access outside 07:00–20:30 (Asia/Bangkok), hardcoded

### Data Flow
1. `LiveClassroom` (read-only, managed=False) — live snapshot from external system
2. `Count` (read-only, managed=False) — viewer counts synced from media servers
3. `Classrooms` — master room registry (admin-editable)
4. `ClassScheduleCenter` — weekly schedule linked to rooms

### Chat System (Polling)
- Client polls `/chat/<room>/messages/?after=<id>&since=<class_start>` every 3 seconds
- Student auth: calls `eshub.ru.ac.th` API → validates student status (A/B/C only)
- Teacher badge: provide `chat_pin` from `Classrooms.chat_pin` (per-room PIN)
- Rate-limited: 10 messages/min per IP via `django-ratelimit`
- Chat auto-disables after last class of the day ends

### Real-time Admin Monitor
- `/monitor-sse/` — SSE endpoint (50-second window, 15-second keepalive)
- `/viewer-data/` — JSON snapshot of all live rooms + viewer counts
- Nginx: SSE path uses `proxy_buffering off` and no caching

### Schedule Data
- `live/data/schedule.json` — banner text, popups, events; editable via `/schedule-editor/` (staff only)

## Key Conventions

**Time handling:**
- `USE_TZ = False` — all datetimes stored as naive Asia/Bangkok local time
- Time comparisons use string HH:MM format (fragile, don't change without testing)
- Always use `pytz.timezone('Asia/Bangkok')` for `datetime.now()`

**IP detection priority:** `X-Real-IP` → `X-Forwarded-For` → `REMOTE_ADDR` (set by university proxy)

**Typo preserved intentionally:** `config.serverMdeia88` (not "Media") — used across frontend JS

**Database:** MySQL with `mysqlclient`; `fix_collation.py` at root fixes character set issues if Thai text breaks

**Static files:** Source in `static/`, output in `staticfiles/` (generated by `collectstatic` on container start)

## External Integrations

- **HLS media servers:** `ram1`, `ram2`, `media.ru.ac.th` — 5 regional servers for video streams
- **eshub API** (`eshub.ru.ac.th`): Student authentication — POST for JWT token, GET to validate student status
- uWSGI `harakiri=300` to handle slow eshub/Google API calls; Nginx proxy_read_timeout=120s

## Known Issues / Constraints

- `ALLOWED_HOSTS = ['*']` and `DEBUG=True` in docker-compose — intentional for this deployment environment
- No test suite (tests.py exists but is empty)
- Learning hours (07:00–20:30) are hardcoded in middleware — not admin-configurable
- Dashboard analytics cached for 5 minutes to avoid heavy MySQL queries
- Nginx blocks Azure/Microsoft IPs and common crawlers (cURL, Scrapy, Python-urllib, Bing bot)
